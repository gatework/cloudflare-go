# 第四轮渐进式审查与改进

基线 `f933a60966cd74a8c3404489767ab7b79bac81e6`，2026-11-01。范围为请求边界、响应收集性能和本地输入检查，不增加批量写入、导入、常驻进程或监控。写入测试均使用本地假 API；节点验收只执行读取。

## 请求结果与资源所有权

| 发现 | 处理和验证 |
|---|---|
| DNS、拨号和 TLS 失败也被当作可能完成的写入 | 标准 `net/http.Transport` 已开始取连接、尚未取得连接或完成 TLS 且没有响应时，可认定未发送。拨号/TLS 回归返回普通失败，用户取消仍为 130 |
| 连接建立后断开、未知自定义传输无法证明未发送 | 保留只读核对与退出码 5；本地服务收到写请求后断开响应，验证只写一次、结果未知。POST/PATCH/DELETE 不重试 |
| `Close` 可能清理调用方共用的外部连接池 | 只关闭客户端自行克隆并拥有的默认传输；显式注入或无法克隆的默认传输均借用。测试分别观察自建空闲连接关闭和外部池保持 |
| 本地 JSON 编码失败被误归类为写入结果未知 | 未进入传输的失败同样携带未发送证据；错误只暴露受控诊断，不输出底层网络错误或凭据 |

取得连接不证明写入成功，仅表示不能再依据连接跟踪断言未发送。有效 Cloudflare 4xx 拒绝仍按既有规则处理，HTTP 408 除外；非标准传输不会因缺少跟踪事件而误判为未发送。注册协议可能绕过标准连接路径，自定义 TLS 拨号也可能缺少事件；这些情形保守保留结果未知，另有注册协议回归先复现再修复。

## 命令级响应额度

字节额度放在命令 context 中，操作超时是其子 context；删除确认或初始化 Zone 选择后可重新计时，字节额度继续累计。列表接口不再接收各自的 `maxBytes`，域服务也不持有重复配置。独立调用 API 时自动创建默认额度，并在调用结束清理。

正文读取在官方 SDK 解码之前计数，包括 HTTP 自动解压后的完整 JSON 包裹、Zone 发现、每页、错误响应、重试和 BIND。默认 256 MiB，单响应仍有 16 MiB 硬上限；检测超限最多额外读取一个字节。超限后关闭响应体、停止后续请求，输出文件不发布。额度是读取约束，不是 RSS 或输出文件上限。

额度通过 `context.WithCancelCause` 区分于用户取消，普通读取超限返回 1。写入已发出而响应读取或后续核对超限时仍返回 5，不能误报为未写入。测试覆盖精确边界、最大 int64 额度、gzip 解压、重试错误正文、Zone 与记录合计、确认/选择不重置、写入后的不确定性。

命令顺序读取响应；额度内部串行化读取，保证显式共享 context 的并发调用也不重复消费额度。没有创建后台读取 goroutine。

## 解码与本地验证

继续使用固定版本官方 SDK 的请求参数、认证和 GET 重试，使用 `option.WithResponseBodyInto` 接收轻量包裹和 `json.RawMessage`，跳过生成联合类型的昂贵解码。分页完整性、ID 核对、排序、未知字段和大整数保真、未匹配记录的摘要去重均保留。Zone 只解码实际使用字段；DNS 原始记录仍通过领域解析器处理。

CLI 在读取凭据前解析补丁和内容文件，校验字段、类型、TTL、已知记录类型约束与参数互斥。名称归属、简写展开和依赖现有类型的检查仍由领域服务完成；服务继续复制补丁以拥有变更快照。没有新增抽象工厂或将 SDK 类型暴露给领域层。

## 性能验收与检查

`scripts/compare_collection.py` 在同一 runner 上交替运行五对基线/候选样本，每次固定 5 次操作，分别比较不筛选与 1% 匹配的完整收集和 JSON 输出；保留堆另以 10,000 条记录采样。门槛为两种场景 B/op 不超过基线 70%、ns/op 不超过 105%，筛选场景保留堆增量不超过 110%。配置固定 `GOMAXPROCS=2`、`GOMEMLIMIT=160MiB`，计时不含 fixture 构建、真实网络和磁盘。CI 保留全部原始输出和结构化比值，任一测量失败或门槛不满足都会阻止交付。具体运行结果随验证完成记录。

检查包括全量/race、vet、Staticcheck、govulncheck、四类输入 fuzz、Python 发布脚本测试、actionlint、模块一致性，以及 Linux/macOS × amd64/arm64 原生测试和精确发行包执行；Linux amd64 重建归档逐字节比较。审查分别按仓库约定与本轮计划核对。

没有改变分页的非事务性、写前比较的非原子性或已进入调用方 Writer 后的阻塞边界。生产节点升级使用通过 CI 的固定提交 dev 归档和校验和，保留回退版本，不修改配置、凭据或现有代理服务。
